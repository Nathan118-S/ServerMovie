Bulk import titles
One title per line: Title | Year | Genre | Rating | imdbId — only Title is required. Ask Claude in chat to look up the details for a list of movies you own and it'll hand you a block in this format to paste here.
Bulk import posters & banners
Select several image files at once, named to match your titles (e.g. Night Circuit.jpg matches "Night Circuit") — each gets matched and attached automatically, used for both the poster card and the hero banner. This can't reach the web, so use images you already have the rights to use.
Bulk import theme songs
Select several audio clips at once, named to match a series (e.g. Night Circuit.mp3 matches the series "Night Circuit") — matched automatically and applied to every disc in that series, so they all share the one theme. Only used where a title has a series name set; keep clips short and under 8MB each. This can't reach the web, so use clips you already have the rights to use.
Auto-fill posters, logos & descriptions
Looks up every title that's missing a poster, logo, or description — checking OMDb and TMDb and merging whatever each finds — and fills them in automatically: genre, rating, IMDb id, poster art, a transparent title-logo image, and a plot summary. TV series are searched as series (not movies), so their year and type actually match. Needs the Pi to have internet access at the moment you use it — everything else in this app keeps working without it.
Don't have one yet? Get a free OMDb key (1,000 lookups/day).
Don't have one yet? Get a free TMDb key — this is also the only source of the title-logo image, and is much better than OMDb for TV series.
Games (IGDB)
OMDb and TMDb only cover movies and TV — games use IGDB (run by Twitch), which needs a Client ID and Client Secret rather than a single key. Fills in poster art, genre, and a description the same way the fields above do for movies.
Don't have these yet? Create an app at dev.twitch.tv/console/apps (free) — IGDB runs on Twitch's developer platform.

Bay sensors & lighting (ESP32 + WLED)
Assign each title to a physical bay number so a microswitch pulling it triggers an automatic checkout, and optionally a lit LED index on a WLED strip so the bay's light reflects whether it's in stock. See README.md for the full ESPHome + WLED setup.
How long after someone logs in with their PIN a bay pull still counts as theirs — long enough to walk over and grab it, short enough that the next person doesn't get blamed for it.
Door animations
If you've wired a separate door sensor (not a bay switch), the whole strip plays a welcome effect when it opens, and a leaving effect once it's stayed closed for a while. Effect IDs are whatever WLED numbers them as on your firmware — check your WLED web UI's effects list, or GET http://<wled-ip>/json/eff, rather than trusting these defaults blindly.
LEDs not tied to any bay — lights up bright white when the door opens (alongside the per-bay colors and the whole-strip effect above) and turns off along with everything else once the door's been closed a while. Leave blank if you don't have any wired for this.
Bay dashboard
Stick a printed bay barcode on each shelf. Then, from Scan a disc, scan a disc that isn't assigned to a bay yet followed by a bay barcode, and it's linked automatically — no need to use the dropdowns below by hand.
Bay layout
Drag each bay to where it actually sits on the shelf, so this matches reality instead of just listing numbers in order. Shows what's really assigned there, its stock status, and a damaged/missing flag — computed the same way Sandy Server decides what color to send WLED, not a true per-LED read-back (WLED's simple API doesn't support that). The indicator above is a genuine live check, though — it actually asks WLED right now whether it's on and reachable.

Restart the hardware
For when a device seems stuck or unresponsive rather than genuinely broken — the same as pulling its power and plugging it back in.
The bay ESP32's restart button is best-effort — ESPHome's exact API for it has shifted across versions, so if it doesn't respond, open its own dashboard directly and use the restart button shown there instead. Needs esphome-bays.yaml's web_server: section, which didn't exist before this — re-flash if you set this up prior to that.
Hardware test & diagnostics
Fire a bay/door event yourself — same effect as the real switch — to check the app side works before touching any wiring, or to narrow down whether a problem is the ESP32 or Sandy Server. The log below shows every call these four endpoints receive, from anywhere, including from your actual hardware — if your ESP32 is reaching the Pi at all, you'll see it show up here the instant you pull a switch, with the IP it came from.

Main kiosk

Support requests
The "Request Support" button in the top-right of the main screen sends a message here — a Discord or Slack incoming-webhook URL both work directly. The URL itself is never shown or sent to anyone browsing the kiosk; it only ever lives here and on the server.
Alert webhooks
Four independent channels — set any, all, or none. Each fires only for its own event, to wherever its own URL points; a Discord or Slack incoming-webhook URL both work directly for any of them.
